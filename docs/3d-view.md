# 3D 운지 보기 (`3d.html`)

37음 운지를 **3D 플루트 + 손가락 모션**으로 보여 주는 화면입니다.
2D 앱의 **배우기** 모드에서 스테이지 오른쪽 위 **「3D로 보기」**로 들어가고, 상단 **「2D 운지표」**로 돌아옵니다.
보고 있던 음과 대체 운지는 URL(`?note=As4&alt=0`)로 두 화면 사이에 그대로 이어집니다.

- 2D 앱(`index.html`)은 설계서 규약대로 **단일 파일 · 외부 의존성 0**을 유지합니다.
- 3D 화면만 같은 출처의 **로컬 Three.js**(`vendor/three-0.170.0/`)를 씁니다. CDN은 쓰지 않고, 서비스워커가 미리 캐시해 오프라인에서도 열립니다.

## 파일

| 경로 | 역할 |
|---|---|
| `3d.html` | 3D 화면 (UI + 3D 뷰어, 한 파일) |
| `vendor/three-0.170.0/` | Three.js r170 로컬 번들 — 버전 올리는 법은 폴더의 `README.md` |
| `sw.js` | `3d.html`·Three.js 프리캐시, 페이지별 오프라인 캐시 |
| `qa/check-3d-data.mjs` | 2D·3D 운지 데이터 동기화 검사 (의존성 없음) |
| `.github/workflows/qa.yml` | PR과 `main` 푸시마다 위 검사 실행 |

## 데이터 동기화 규칙

`KEY_IDS` · `NOTES` · `ARIA_FINGER` · `KEY_GROUP`의 원본은 `index.html`입니다.
`3d.html`의 `@DATA-SYNC-START` ~ `@DATA-SYNC-END` 블록은 그 복사본입니다.
(`index.html`의 단일 파일 규약 때문에 데이터를 외부 파일로 빼지 않았습니다.)

운지를 고칠 때는 **두 파일을 함께** 고치고 아래를 실행하세요. GitHub Actions에서도 자동으로 검사합니다.

```bash
node qa/check-3d-data.mjs
```

## 3d.html 구조

| 구역 | 내용 |
|---|---|
| 1. 운지 데이터 | `index.html`과 같은 선언 |
| 2. 앱 상태 | `noteId` · `altIndex` · `region`(auto/all/left/right/foot/free) · `view`(player/mirror/top) · 표시 옵션 |
| 3. 3D 뷰어 `createViewer()` | 장면 · 플루트 · 15키 · 손 · 손가락 IK 솔버 · 카메라. 밖에는 `show(keys, {on, off, diff})`, `frame(region)`, `setView()`, `setHandsVisible()`, `setGhost()`만 노출 → **메시를 Blender GLB로 바꿔도 UI 코드는 그대로** |
| 4. 화면(UI) | 음 정보 카드 · 보기 영역 버튼 · 대체 운지 탭은 2D 앱 컴포넌트와 같은 모양·문구. **오른쪽 패널(음 고르기·보기 설정)은 3D 전용으로 단순화**(아래 「오른쪽 패널」) |
| 5. 시작 | UI를 먼저 그리고, WebGL 2가 될 때만 Three.js를 동적으로 불러옴. 안 되면 안내 문구 + 2D 링크 |

### 동작

- **키 눌림**: 키가 로드(회전축)를 중심으로 돌아가고(롤러는 눌려 들어감) 손가락 그룹 색으로 빛납니다.
- **손가락**: 키 접촉점과 접근 방향을 목표로 좌표 하강 IK(관절 한계 · 휴식 자세 · 관 관통 벌점)를 풀고 240ms로 보간합니다. 새로 누르는 손가락만 40ms씩 차례로 움직입니다(2D 앱과 같은 연출).
- **오른손 이동**: 새끼손가락이 C♯·C 롤러로 갈 때 손 전체가 풋 쪽으로 1.2·2.4cm 이동합니다.
- **변화 강조**: 새로 누른 키는 초록 링, 뗀 키는 빨강 링 (2D의 `changed-on`/`changed-off`와 같은 의미).
- **카메라**: 「자동」이면 바뀐 키가 몰린 영역으로 이동합니다(2D `deriveCameraPreset`과 같은 규칙). 사용자가 직접 돌리거나 확대하면 자동 이동을 멈춥니다.
- **렌더링**: 애니메이션·조작 중에만 그립니다(대기 중 0fps, 모바일 배터리 절약).
- **소리**: 3D 화면에는 없습니다. 소리는 2D 앱에서 재생됩니다.

### 오른쪽 패널 (음 고르기 · 보기 설정)

처음 버전은 음 버튼 37개와 표시 옵션 4개가 한꺼번에 보여서 복잡했습니다. 지금은 한 장의 카드로 줄였습니다.

- **옥타브 3칸 + 계이름 버튼 목록**: 「1옥타브 낮은 음 / 2옥타브 가운데 음 / 3옥타브 높은 음」 중 고른 옥타브의 계이름 버튼만 보입니다(나머지는 `hidden`이라 탭 순서에서도 빠집니다).
- **계이름 버튼은 1열 종대(세로 한 줄)**: 낮은 음 → 높은 음 순서로 반음 단위 12개(3옥타브는 C7까지 13개)를 위에서 아래로 쌓습니다. 흰 버튼은 온음, 검은 버튼은 반음(♯)이고, 왼쪽에 한글 계이름 · 오른쪽에 영문 음이름이 놓입니다. 버튼은 폭이 패널 가득, 높이가 44px 이상이라 손가락으로 누르기 좋습니다. 데스크톱(1024px 이상)에서는 패널이 오른쪽 열에 `position: sticky`로 놓이는데, 세로 목록 때문에 패널이 왼쪽 열보다 길어질 수 있어서 그리드 세 번째 행을 `1fr`로 두었습니다(남는 높이를 맨 아래 행이 받아서 3D 화면과 손가락 요약 사이가 벌어지지 않습니다). 화면이 낮은 노트북에서는 페이지를 조금 내려 아래쪽 버튼과 「보기 설정」을 봅니다. 모바일·태블릿(1024px 미만)에서는 패널이 3D 화면 아래에 이어지고, 화면 높이가 600px 이상이면 3D 화면이 위에 고정된 채 버튼 목록이 그 아래로 지나갑니다.
- **목록 안에서는 스크롤하지 않음**: 버튼이 모두 펼쳐져 있어서 고른 음을 목록 가운데로 가져오는 코드는 없습니다. 음이 바뀌어도(탭 · 숫자 단축키 · ←/→/↑/↓ · 이전/다음 · 자동 재생) 페이지 스크롤 위치는 그대로이고, 옥타브가 바뀌면 그 옥타브의 목록이 열립니다. 목록에 스크롤 영역이 없어서 포커스 링(3px+2px)과 선택한 버튼의 빛(3px)이 잘리지 않습니다.
- **옥타브 버튼 = 지금 음을 같은 계이름으로 옮김**: D♯5에서 「3옥타브」를 누르면 D♯6이 됩니다(↑/↓ 키와 같은 동작). 그래서 보이는 목록에는 항상 선택한 음이 있습니다. 키보드(숫자 단축키 · ←/→/↑/↓), 이전/다음 버튼, 자동 재생으로 음이 바뀌어도 목록이 그 옥타브로 따라갑니다.
- **선택한 음**은 금색(`--accent`) 채움 하나로 표시합니다(예전의 ✓ 배지는 뺐습니다). 강제 색상 모드에서는 3px 윤곽선으로 보입니다.
- **보기 설정**(손 보이기 · 손 반투명 · 달라진 키 표시 · 천천히 움직이기)은 기본으로 접혀 있고, 펼치면 `role="switch"` 스위치 4개와 키보드 안내가 나옵니다. 기본값은 손 켬 · 반투명 끔 · 달라진 키 켬 · 천천히 끔입니다.
- **키보드 단축키(2D 앱과 같음)**: 숫자 1~7 = 도~시(C4~B4) · Shift+1~7 = 높은 도~시(C5~B5) · Alt+1~5 = 반음 도♯/레♭ · 레♯/미♭ · 파♯/솔♭ · 솔♯/라♭ · 라♯/시♭(C♯4~A♯4) · Alt+6~0 = 높은 반음(같은 순서, C♯5~A♯5) · ←/→ 반음 · ↑/↓ 옥타브. 숫자는 키보드 위쪽 줄만 씁니다(`event.code` 기준이라 Shift를 눌러 기호가 나와도, 한글 입력 상태여도 같은 키로 인식). 표는 `NOTE_SHORTCUTS` 하나이고 `index.html`에 같은 표가 있으며, `qa/check-3d-data.mjs`(GitHub Actions `data-sync`)가 둘이 같은지 검사합니다. 표에 없는 조합(숫자만 또는 Shift로 누른 8·9·0, Ctrl, Shift+Alt 등)은 브라우저 기본 동작을 막지 않습니다. 단축키는 모두 24개이고, 한 음에 단축키는 하나뿐입니다(`qa/check-3d-data.mjs`가 겹침도 검사).
- 코드는 `buildSelector()`(버튼 생성) · `showOctave()`(옥타브 전환) · `bindUi()`의 `#selector3d` 클릭 처리에 있습니다. 옥타브 1~3(옥타브마다 12~13개)을 가정하며, 음 범위가 달라져도 목록은 버튼 수만큼 그대로 길어집니다. 버튼 모양은 CSS `.piano`(`flex-direction: column`)와 `.note-btn`(`min-height: 44px`, 폭은 패널 가득)으로 정합니다.

## 좌표 · 자세 규약

- 단위 cm. 플루트 축 = X(머리관 0 → 풋 67), 위 = +Y, 연주자 쪽 = +Z, 관객 쪽 = −Z.
- 키컵은 관 위(φ ≈ 8°), 본체 로드는 관객 쪽(φ ≈ 70°). 엄지 키는 뒷면·연주자 쪽(L1–L2 사이), G♯ · 사이드 B♭ · 트릴 · E♭ · 롤러 터치피스는 연주자 쪽.
- **왼손**: 손바닥이 연주자 쪽. 손가락이 관객 쪽에서 관 위를 넘어와 키컵을 누르고, 엄지는 관 아래로 돌아 엄지 키를 누릅니다.
- **오른손**: 손등이 연주자 쪽. 손가락이 연주자 쪽에서 관 위를 넘어가고, 엄지는 관 아래를 받칩니다.
- 시점: **연주자**(+Z 위에서 내려다봄) · **거울**(−Z, 마주 선 선생님 방향) · **위**.

## Blender 모델로 교체할 때의 이름 규약

운지 데이터와 솔버는 그대로 두고, 아래 이름을 가진 GLB로 메시만 바꾸면 같은 모션이 적용되도록 이름을 맞춰 두었습니다.

| 오브젝트 / 본 | 규칙 |
|---|---|
| `key_L1` … `key_lowC` (15개) | `key_` + KEY_ID. 원점(피벗)은 로드(회전축) 위, 로컬 X축 회전 = 눌림. 롤러는 이동 |
| `hand_L`, `hand_R` | 손 루트. 아마추어 1개씩 |
| `L_index_mcp` / `_pip` / `_dip` (`middle` · `ring` · `pinky`도 같은 형식) | 손가락 관절 본. `mcp`는 굽힘(X) + 벌림(Y), `pip` · `dip`는 굽힘(X) |
| `L_thumb_cmc` / `_mcp` / `_ip` | 엄지 본. `cmc`는 2축 |
| `L_index_tip` 등 `*_tip` | 손끝 엠프티. 솔버가 이 점을 키 접촉점으로 보냄 |
| 재질 `mat_key_*` | 키마다 별도 재질 (눌림 색을 키별로 제어) |

권장: 실측 cm 스케일, 삼각형 10만 개 이하, Draco/Meshopt 압축, 텍스처 KTX2.

## 수동 QA 체크

- 2D 배우기 모드에서만 「3D로 보기」가 보이고(퀴즈·직접 누르기에서는 숨김), 누르면 같은 음·대체 운지로 열린다.
- 3D에서 음을 바꾼 뒤 「2D 운지표」로 돌아가면 그 음이 선택돼 있다.
- 함정 음 D4·D5·D6, 대체 운지 A♯4(3종), 롤러 C4·C♯4, 트릴 B♭6·B6의 손가락이 해당 키에 닿는다.
- 오른쪽 패널: 옥타브 버튼을 누르면 같은 계이름으로 옮겨지고 계이름 버튼 목록에 선택한 음(금색)이 보인다. C7은 3옥타브에서만 있다. 「보기 설정」은 접혀 있고 펼치면 스위치 4개가 나온다.
- 계이름 버튼은 세로 한 줄(1열)로 쌓이고 폭이 모두 같다. 어떤 음을 골라도 그 버튼이 금색으로 채워지고, 목록 안에서는 스크롤되지 않는다(페이지만 스크롤). 모바일에서는 3D 화면이 위에 고정된 채 버튼이 그 아래로 지나가고, 화면 높이가 낮은 노트북에서는 페이지를 조금 내려 아래쪽 버튼과 「보기 설정」을 본다.
- 키보드 숫자 1~7(도~시) · Shift+1~7(높은 도~시) · Alt+1~5(반음) · Alt+6~0(높은 반음)으로 2D·3D 모두 같은 음이 골라진다(24개). 2D에서는 그 단축키의 탭(낮은 계이름 · 높은 계이름 · 반음)이 펼쳐지고 안내 표의 그 칸이 반짝인다. Windows에서는 Alt를 왼쪽 키로 누른다(오른쪽 Alt는 한/영 키).
- 앱을 한 번 연 뒤 오프라인에서 2D·3D 화면이 각각 제대로 열린다.
- WebGL을 끈 브라우저에서 안내 문구와 2D 링크가 나온다.
